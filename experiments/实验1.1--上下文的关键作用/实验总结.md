# 实验 1.1 总结：上下文的关键作用

## 一、实验目的

同一道题、同一个模型，**每组只从输入里移除一类上下文信息**，观察模型行为如何变化。

要回答的问题：模型的表现，取决于它这一轮实际收到了什么，还是取决于系统后台算出了什么？

## 二、实验设置

| 项目 | 内容 |
|---|---|
| 模型 | `deepseek-v4-flash`（DeepSeek 直连） |
| 运行日期 | 2026-11-26 |
| 任务 | 四季度收入（Q1 250 万美元 / Q2 210 万欧元 / Q3 180 万英镑 / Q4 3.8 亿日元），非美元季度换成美元后求年度合计与季度均值，保留两位小数 |
| 标准答案 | 合计 `9,602,895.73`；均值 `2,400,723.93` |
| 可用工具 | `parse_pdf`、`convert_currency`、`calculate`、`code_interpreter` |
| 迭代上限 | 5 轮 |
| 总消耗 | 23,956 tokens |

### 五组消融

| 组 | 移除的东西 | 实现位置（`agent.py`） |
|---|---|---|
| `full` | 无（基线） | —— |
| `no_history` | 历史消息 | `_prepare_messages_for_api()` 只发 system + 题目 |
| `no_reasoning` | 历史里的 `reasoning_content` | `_prepare_assistant_message()` 写回前剥离 |
| `no_tool_calls` | 工具定义 | 请求中不带 `tools` 参数 |
| `no_tool_results` | 工具执行结果 | `role: tool` 消息内容置为空字符串 |

|---|---:|---:|---|---|---|

| `no_history` | **5** | **15** | **9** | **是** | `no_terminal_response` |
| `no_reasoning` | 3 | 4 | 0 | 否 | `correct` |
| `no_tool_calls` | 1 | 0 | 0 | 否 | `no_unsupported_numbers` |

## 四、结论

1. 没有轨迹，上下文只有系统提示词，用户问题，工具定义。导致模型每一轮只会重复调用工具。
2. 没有思考内容，模型输出可能不受影响。主要看思考内容在上下文其它位置找不找得到。
3. 没有工具定义，模型会直接回答缺少工具。
4. 没有工具执行结果，模型会一直重复调用工具。
5. 在没有工具定义的时候，去掉“不要自己估汇率”那句。模型会自己去编造工具。
6. 在把工具执行结果遮掩之后，模型会尝试单次调用。一直想办法绕过遮掩。

核心结论：模型的行为取决于它这一轮实际收到的上下文，而不取决于系统后台算出了什么。不同模型在本实验的输出结果不一致。

## 五、两个补充实验（反例）

### 补充实验①：去掉题目中“不要自行估计汇率”的约束

同一组（`no_tool_calls`），仅移除提示词里那一句限制。

| | 有约束（标准） | 无约束 |
|---|---|---|
| 表现 | “没有换汇工具，算不了” | 输出一段伪造的 `<tool_call>` 文本 |
| 真实工具调用 | 0 | 0 |
| 是否编造数字 | 否 | 否（但思考里已准备编造） |

思考原文（关键句）：*“I'll assume typical rates... maybe I should just compute with reasonable rates and note assumptions.”*
——它曾计划自行补汇率并注明假设，最终改主意伪造工具调用。**未编造数字属于偶然，不是可靠性的证明。**

### 补充实验②：把抹掉的工具结果换成可见提示语

`no_tool_results` 组，把空字符串换成 `[Tool result hidden due to context mode]`。

| | 空字符串（标准） | 可见提示语 |
|---|---|---|
| 轮数 | 4（主动停） | **5（撞上限）** |
| 工具调用 | 9 | 6 |
| 最终回答 | 766 字，说明六次尝试均无结果 | **空（`null`）** |
| 判定 | `no_unsupported_numbers` | `no_terminal_response` |

原因：提示语让模型把问题定性为“数据存在但被挡住”，于是不断尝试绕过（包括试图用 Python 联网查汇率），而不是放弃并报告。**多一个信号，结论就变了——这说明“消融观测”与“消融信号”是不同的实验。**

## 六、与书中记录的差异

书中记录基于 Kimi K3。

| 项目 | 书中（Kimi K3） | 本次（DeepSeek） | 是否一致 |
|---|---|---|---|
| `no_reasoning` | 答对，无可测退化 | 答对，无可测退化 | ✅ 一致 |
| `no_tool_results` | 9 次调用后撞到上限 | 9 次调用后主动停止 | ❌ 不同 |
| 无约束任务下的 `no_tool_calls` | 自行补汇率，报出 `$9,587,333.33` | 伪造工具调用文本，未报数字 | ❌ 不同 |
| 可见提示语的效果 | 撞顶率显著下降 | 反而撞到上限、空手而归 | ❌ 方向相反 |

**结论：消融结果与开关效果都依赖具体模型，不能作为通用定律。**

## 七、局限

- 每个组只跑了一次，模型输出具有随机性，重复运行可能得到不同结果。
- 汇率为固定值，非实时。
- 仅测试了一个模型，无法区分“消融的影响”与“该模型的特性”。
- `groundedness` 在模型看到过观测时会返回 `not_assessable`，此时无法区分“读到的”与“心算的”。
