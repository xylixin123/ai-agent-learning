# 实验 2.1 总结：本地 LLM 服务部署与工具调用

## 一、实验目的

在自己电脑上部署本地 LLM（Ollama + qwen3:0.6b），跑通"工具调用"的完整流程：

**模型不会算/不知道 → 发出工具调用 → 客户端执行工具 → 结果回灌 → 模型作答**

并练习"分析结果"：判断模型回答里的每个数字是否可信、来自哪个工具。

## 二、实验设置

| 项目 | 内容 |
|---|---|
| 模型 | `qwen3:0.6b`（Ollama 本地，约 522 MB，约 7.5 亿参数） |
| 环境 | 原生 Windows，Python 3.12.10，Ollama 0.40.18 |
| 后端 | Ollama 原生接口（`main.py --backend ollama`） |
| 任务 | 温哥华当前时间 + 天气（要求同时调用两个工具） |
| 可用工具 | `get_current_time`、`get_current_temperature`、`convert_currency`、`code_interpreter` |
| 运行方式 | 单任务模式 `python main.py --backend ollama --mode single --task "..."` |
| 运行日期 | 2026-11-27 |

## 三、结果

模型一次发出两个工具调用，客户端**并行执行**：

| 环节 | 内容 |
|---|---|
| 模型发出的调用 | `get_current_time(timezone=America/Vancouver)` + `get_current_temperature(location=Vancouver, unit=celsius)` |
| 时间工具回执 | `2026-11-26 23:51:17`（UTC-7） |
| 天气工具回执 | `8.0°C`、overcast（阴天）、湿度 82%、风速 9.7 km/h、`timestamp: 23:45`、来源 Open-Meteo |
| 模型最终回答 | `Current Time: 23:45`；`Weather: Overcast, 82% humidity, 9.7 km/h` |

## 四、关键发现：时间"串源"

模型回答的"当前时间 **23:45**"对不上时间工具的 **23:51:17**，而是**恰好等于天气工具的 timestamp（23:45，天气观测时间）**。

| 工具 | `timestamp` 含义 | 代码位置 | 值 |
|---|---|---|---|
| 时间工具 | **真正的当前时间** | `tools.py` 第 305 行 `current_time.isoformat()` | `23:51:17` |
| 天气工具 | **天气观测时间**（不是当前时间） | `tools.py` 第 223 行 `current.get("time")` | `23:45` |

**根源**：两个工具都返回一个叫 `timestamp` 的字段，但含义不同。模型把天气的观测时间当成了当前时间——坑埋在 `tools.py` 第 223 行。

此外，模型还**漏提了气温 8.0°C**。

## 五、结论

1. React流程：用户提问->模型申请工具调用->main执行工具并返回结果 ->模型根据结果判断是否继续申请工具调用。
2. 模型在获取指定工具结果时，可能被其它工具的相同字段影响，会改变正确答案。
3. 必要在harness加上验证。

## 六、与归档记录的差异

| | 随书归档（2026-07-29，macOS） | 本次（2026-11-27，Windows） |
|---|---|---|
| 时间工具 | `11:11:28` | `23:51:17` |
| 天气工具 | `17.9°C`，mainly clear | `8.0°C`，overcast |
| 模型答时间 | `11:11`（与工具一致） | `23:45`（串了天气 timestamp） |
| 模型答天气 | `17.9°C` | 漏提气温 |

差异原因：① 时间/天气是实时的（夏 vs 冬）；② 小模型本身有随机性和不稳定性。

## 七、局限

- 只跑了一次，模型输出具有随机性；
- 只测了一个小模型（qwen3:0.6b），不代表更大模型的行为；
- 时间/天气是实时数据，无法复现同一组数值；
- 本次结果来自终端输出，**未用 `run_experiment.py` 归档成文件**。
