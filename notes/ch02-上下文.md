# 第 2 章：上下文

## 本章一句话
上下文再模型固定的情况下，是影响agent性能的关键因素。
上下文由系统提示词，工具定义，轨迹再加上状态栏，模型对靠后上下文的注意力越强。

kv cache是模型的根据之前上下文计算的的缓存，存放在显存中，缓存可以复用的前提是，上下文不变。因此好的上下文是
1. 系统提示词和工具定义一旦确定就不要改。
2. 动态信息永远追加到末尾。
3. 使用标准 API 格式，不要自行拼接消息。因为模型是由api格式训练的。

系统提示词，不是越多越好，越多会被稀释注意力。用流程组织，内容细化，少让模型猜测，适当放一些例子说明模型回复风格。
工具定义有名称，描述，以及参数。
模型不应该无条件相信上下文，需要对上下文进行检验。

上下文除了上面的api格式，还有skill.md文件，agent可以快速使用它来获得特定技能，比如写文件。但是技能越多，skill文件越多，导致上下文被浪费，所以采用的是渐进式纰漏，目录常驻，内容按需加载。

状态栏，由于agent极强的检索能力，但缺少概括，总结能力。因此需要状态栏。
状态栏由任务规划，事件的时间，位置等，括动态的环境信息、异常操作提醒、以及从隐式状态到显式观察的转换。
由于状态栏是在框架输入上下文给模型之前，追加在上下文末尾的。因此模型比较关心状态栏。
状态栏更新有
1. 每轮替换，代价是后面的缓存不能复用。
2. 持续追加，代价是浪费上下文。


前面讲的是上下文构成，但是上下文是一直追加的，窗口有限，并且注意力会被无用的消息稀释，因此需要压缩上下文。压缩虽然会导致缓存失效，但是不压缩会导致任务失败。
压缩方法：
1. 工具大输出存磁盘，上下文只给摘要
2. 噪声直接删除。
3. API 层微压缩：让服务端从前缀里把某段工具结果去掉，本地消息不动。
4. 归档式摘要：逐轮做结构化摘要。
5. 全量压缩（最后手段）​：用 LLM 完整压一遍。还分两阶段：先压会话记忆，不行才全量。

隔离优于压缩：子 Agent 上下文隔离。
